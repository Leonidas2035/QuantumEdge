3) Scalping Strategy - Indicators/Features Used NOW
3.A Main ML scalper (default runtime path)
Feature computation path:
- Data source: tick trades (event fields p=price, q=qty, m=side) and optional microstructure events; event parsing in bot/run_bot.py:640-773.
- Online feature vector: computed in bot/ml/features/builder.py:45-132 with names in bot/ml/feature_schema.py:19-43; invoked from bot/run_bot.py:773.

Returns / volatility features (tick -> 1s bars):
- Names: ret_1s, ret_5s, ret_30s, ret_60s
  - Type: return indicators
  - Source data: tick price aggregated to 1s bars (build_feature_frame, bot/ml/features/builder.py:63-77)
  - Implementation: bot/ml/features/builder.py:74-77
  - Called from: bot/run_bot.py:773 -> bot/ml/features/builder.py:158-173
  - Parameters/windows: pct_change(1/5/30/60)
  - Output: float (part of np.ndarray feature vector)
  - Performance: computed via pandas resample + rolling each tick (O(n) per tick)
- Names: vol_5s, vol_30s, vol_60s
  - Type: volatility indicators
  - Source data: ret_1s rolling std on 1s bars
  - Implementation: bot/ml/features/builder.py:78-80
  - Called from: bot/run_bot.py:773 -> bot/ml/features/builder.py:158-173
  - Parameters/windows: rolling std(5/30/60)
  - Output: float
  - Performance: rolling std recomputed each tick (O(n) per tick)

VWAP / trend features:
- Names: vwap_1s, vwap_5s, vwap_30s, vwap_60s
  - Type: VWAP indicators
  - Source data: bar price/qty
  - Implementation: bot/ml/features/builder.py:69-90 (roll_vwap windows 5/30/60; vwap_1s uses 1s bar)
  - Called from: bot/run_bot.py:773
  - Parameters/windows: rolling sum windows 5/30/60
  - Output: float
  - Performance: rolling sums per tick
- Names: ema_slope_5s, ema_slope_30s
  - Type: trend indicators (EMA slope)
  - Source data: 1s bar price
  - Implementation: bot/ml/features/builder.py:92-95 (EMA spans 5/30; slopes are diffs)
  - Called from: bot/run_bot.py:773
  - Parameters/windows: EMA span 5/30
  - Output: float

Order-flow / imbalance features:
- Names: imb_5s, imb_30s
  - Type: order-flow imbalance indicators
  - Source data: side_sign and qty on 1s bars
  - Implementation: bot/ml/features/builder.py:97-103 (rolling window 5/30)
  - Called from: bot/run_bot.py:773
  - Parameters/windows: rolling sum over 5/30 seconds
  - Output: float

Volume / liquidity features:
- Names: vol_spike_5s, vol_spike_30s
  - Type: volume spike ratios
  - Source data: bar qty
  - Implementation: bot/ml/features/builder.py:105-107 (rolling means / 30s mean)
  - Called from: bot/run_bot.py:773
  - Parameters/windows: rolling mean 5/30 vs 30s mean
  - Output: float

Regime feature:
- Name: regime_tag
  - Type: regime classification (numeric)
  - Source data: vol_30s + ema_slope_30s
  - Implementation: bot/ml/features/builder.py:33-41 (rules), applied at bot/ml/features/builder.py:109
  - Called from: bot/run_bot.py:773
  - Parameters: vol_30s threshold 0.002; slope sign
  - Output: int-like float in vector

Microstructure features (from MarketDataHub microstructure events, cached):
- Names: ofi_z, ofi_ma5, spread_bps, top_qty_sum, trade_rate_1s, volume_1s
  - Type: orderflow/microstructure indicators
  - Source data: microstructure events via HubMarketDataSource; cached in bot/market_data/microstructure_cache.py:20-37
  - Implementation: injected into bars in bot/ml/features/builder.py:111-120
  - Called from: bot/run_bot.py:648-667 (cache update) and bot/run_bot.py:771-773 (feature builder update)
  - Parameters: none in builder; cache max_age_ms from config (config/settings.yaml:26-29)
  - Output: float

Additional runtime feature usage (non-ML gating, still in scalper path):
- Pre-trade block filter uses feature indices [0], [7], [10] (bot/ml/ensemble.py:104-114) called at bot/run_bot.py:779. Intended to use ret_1 and ret_std_10/vol_sum_10; see Issues for schema mismatch.
- LLM risk moderator uses shock = abs(features[0]) (bot/run_bot.py:837-842), so ret_1s impacts approve/deny.
- ScalpExecutionMode gate uses spread_bps and depth_usd from last_event (bot/trading/execution_mode.py:178-185) and ofi_ma5 from microstructure (bot/trading/execution_mode.py:189-199); called at bot/run_bot.py:947-957.

7) Issues Found (Actionable)
- Missing import for EnsembleSignalModel causes NameError at runtime when features are present. Evidence: bot/run_bot.py:779 uses EnsembleSignalModel.filter_blocks but bot/run_bot.py:20 only imports EnsembleOutput.
- Feature index mismatch in EnsembleSignalModel.filter_blocks: features[7] and features[10] are treated as ret_std_10 and vol_sum_10 (bot/ml/ensemble.py:104-114), but schema index 7 is vwap_1s and 10 is vwap_60s (bot/ml/feature_schema.py:29-33). Gate logic uses wrong inputs.
- Regime tag lookup uses features[-1] in DecisionEngine (bot/engine/decision_engine.py:169-175), but feature schema appends microstructure features after regime_tag; features[-1] is volume_1s (bot/ml/feature_schema.py:19-43). Regime gating is effectively reading microstructure volume, not regime_tag.
- Warmup configuration mismatch: runtime uses config.get("ml.warmup_seconds", 600) at bot/run_bot.py:501, but config/settings.yaml has app.warmup_seconds and no ml.warmup_seconds (config/settings.yaml:1-17). Warmup may be unintentionally fixed to 600s.
- Performance hazard: FeatureBuilder._compute rebuilds a pandas DataFrame and resamples/rolls on every tick (bot/ml/features/builder.py:158-172 and :63-107). This is O(n) per tick and can become a hot-path bottleneck under high tick rates.
- NaN handling: build_feature_vector returns None if any NaN (bot/ml/features/builder.py:125-131), causing bot/run_bot.py:776-778 to skip trading; this may lead to extended no-trade periods after data gaps.
