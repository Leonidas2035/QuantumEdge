2. КОМПОНЕНТИ СИСТЕМИ ТА ЇХНЯ РОЛЬ
--------------------------------------------------------------------------------

### 1. MarketDataHub (MDH)
* **Функція**: Центральний вузол збору ринкових та приватних даних (Data Plane).
* **Складові**:
  - *Ринкові фіди*: `BinanceFuturesFeed` споживає потоки Websocket. У разі обмежень IP використовується `MockLiveFeed`.
  - *Внутрішня шина*: `EventBus` забезпечує потокобезпечний асинхронний розподіл подій всередині модуля.
  - *Аналітичні блоки*: `AlphaEngine` розраховує активність великих гравців (`market.alpha.whale`). `OrderBookAggregator` аналізує великі лімітні плити ліквідності (`market.walls`) та розраховує динамічний VWAP.
  - *Користувацькі фіди*: `BinanceUsdmUserStream` та `BinanceSpotUserStream` підключаються до приватних User Streams для отримання миттєвих повідомлень про угоди, зміну балансу та ліквідаційні ціни.
  - *REST Snapshot Server*: Слухає порт HTTP `8765`, надаючи торговим ботам швидкі знімки ринку для швидкого холодного старту (warm start).

### 2. QuestDB (TSDB)
* **Функція**: Високопродуктивна база даних часових рядів для накопичення ринкової історії та телеметрії.
* **Складові**:
  - *Запис (Write Path)*: `QuestILPWriter` відправляє тики, свічки, знімки склянок та ліквідації через Influx Line Protocol (ILP) на порт TCP `9009`.
  - *Захист від дублікатів*: Оскільки QuestDB використовує WAL (Write-Ahead Logging) з суворими часовими мітками, MarketDataHub динамічно додає наносекундні зміщення (`_get_next_offset`) до записів у межах одного пакету для уникнення колізій.
  - *Запити (Query Path)*: Запити виконуються через PostgreSQL wire protocol (порт `8812`) або REST API (порт `9000`).

### 3. Шина ZeroMQ (ZMQ Bus)
* **Функція**: Асинхронний мікросервісний транспорт з низькою затримкою.
* **Мапа Портів (Source of Truth)**:
  - **Port 5555 (MarketDataHub PUB)**: Трансляція ринкових тиків (`trade.*`), склянок (`depth_l2.*`), великих плит (`market.walls`), метрик (`market.metrics`) та оновлень балансу акаунту (`hub.account_delta.*`).
  - **Port 5556 (Supervisor/Hermes PUB)**: Розсилка команд керування та оновлень політик ризиків (`CMD_TOPIC` / `POL_TOPIC`) від Hermes до ботів.
  - **Port 5557 (Bots PUB / Supervisor SUB)**: Прийом статусних конвертів (`STATUS_TOPIC`) та підтвердження команд (`ACK_TOPIC`) від запущених ботів назад до Hermes.
  - **Port 5558 (Bots Telemetry PUB)**: Передача розширеної телеметрії та метрик латентності ботів для моніторингу.
  - **Port 5559 (Policy Port Override)**: Використовується окремими HFT модулями (наприклад, AI Scalper) для прямої синхронізації ML-політик.

### 4. Hermes Agent (Orchestrator)
* **Функція**: Зовнішній керуючий агент (Control Plane), розташований у директорії `/home/korben/.hermes`.
* **Складові**:
  - *Process Lifecycle*: Керує процесами `MarketDataHub`, торгових ботів та QuestDB, забезпечуючи автоматичний перезапуск при падінні.
  - *LlmSupervisor*: Періодично збирає системний стан, аналізує торгові журнали та рівень просадки (drawdown), після чого викликає Google Gemini API (модель Gemini 3.1) для розрахунку ризик-параметрів.
  - *ZMQ Directives*: За результатами аналізу LLM надсилає на порт `5556` директиви з новими ризик-множниками (`risk_multiplier`), цільовим капіталом (`capital_exposure_pct`) та зміщенням сітки (`grid_bias`).
  - *Делегація на Antigravity (agy)*: Для вирішення нетривіальних завдань моніторингу або виправлення коду Hermes асинхронно викликає CLI `antigravity`.
    1. Створюється файл запиту `runtime/agy_request_*.json` з описом завдання.
    2. Викликається команда `/usr/bin/antigravity chat -m agent` з передачею файлу контексту.
    3. Hermes опитує файлову систему в очікуванні відповіді `runtime/agy_response_*.json`.
    4. Отриманий результат інтегрується в логіку прийняття рішень Hermes.

--------------------------------------------------------------------------------
3. АЛГОРИТМ ВЗАЄМОДІЇ ТА ОБМІНУ ДАНИМИ
--------------------------------------------------------------------------------

1. MarketDataHub отримує ринкову подію (наприклад, угоду на Binance Futures).
2. MDH публікує подію у топік `trade.btcusdt` на порт `5555` і одночасно записує в QuestDB на порт `9009`.
3. Бот (AI_Scalper / LockBotBtc), підписаний на порт `5555`, обробляє подію, оновлює внутрішні фічі та оцінює торгові сигнали.
4. Бот періодично надсилає свій статус (PnL, позиція, маржа) на порт `5557` у форматі `StatusEnvelope`.
5. Hermes Agent читає статус ботів з порту `5557`. Раз на встановлений проміжок часу `LlmSupervisor` ініціює аудит.
6. За необхідності оцінки настроїв ринку, Hermes запускає `agy` для аналізу новин, отримує від нього оцінку ринкового сентименту (Sentiment Score від -1 до 1) та інтегрує її в промпт для Gemini.
7. Gemini формує нову політику ризиків (структурований JSON `LlmGridPolicy`), яку Hermes публікує на порт `5556`.
8. Боти отримують директиву з порту `5556` і негайно перебудовують свої сітки або призупиняють торги відповідно до вказівок Hermes.
