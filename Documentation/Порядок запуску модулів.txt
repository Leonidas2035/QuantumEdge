Усі процеси оркеструються через наш головний скрипт QuantumEdge.py, але для повного розуміння нижче детально описано, як цей процес відбувається під капотом (і як запускати модулі поетапно для дебагінгу або моніторингу).

Порядок запуску модулів (Bootstrapping Sequence)
------------------------------------------------
Правильний запуск відбувається знизу вгору: Сховище (QuestDB) -> Data Plane (MarketDataHub) -> Control/Telemetry Plane (FastAPI Dashboard API) -> Execution Plane (Торгові боти).

Етап 0: Інфраструктура та Сховище (QuestDB)
------------------------------------------
Жоден модуль не повинен стартувати, якщо немає куди писати логі, тики та телеметрію.
QuestDB використовується як основна часорядова база даних.
* Впроваджено високопродуктивний запис через протокол Influx Line Protocol (ILP) на порт 9009.
* Читання історичних даних для прогріву та аналітики здійснюється через HTTP REST API на порту 9000.
* PostgreSQL API працює на порту 8812.

Команда запуску (Docker Compose):
  docker-compose up -d questdb

Перевірка: Відкрити веб-консоль за адресою http://localhost:9000 і впевнитись, що БД активна.

Етап 1: MarketDataHub (Data Plane)
----------------------------------
Сутність: Це "серце" системи постачання ринкових даних. Після міграції з Binance вся робота повністю переведена на BingX.
Процес:
* Підключається до BingX через WebSocket (`BingXLiveFeed`) для отримання L2 depth (стакан ордерів) та трейдів у реальному часі.
* Нормалізує отримані дані та обчислює математичну середню ціну (`mid_price`) та спред, які транслюються як Single Source of Truth (SSOT).
* Відкриває ZMQ PUB сокет на порту 5555.
* Запускає асинхронний фоновий `ilp_writer` для стрімінгу тиків і фіч безпосередньо в QuestDB на порт 9009.

Команда ізольованого запуску:
  python -m src.quantum_edge_core.market_data.hub

Очікуваний лог:
  [MarketDataHub] ZMQ Publisher bound to tcp://*:5555. ILP Writer connected to 127.0.0.1:9009.

Етап 2: Dashboard API / Hermes Bridge (Control & Telemetry Plane)
----------------------------------------------------------------
Сутність: Локальний керуючий інтерфейс та міст для автономного LLM-агента Hermes. Legacy-модуль `SupervisorAgent` повністю вилучено.
Процес:
* Піднімає FastAPI-сервер на порту 8765.
* Запускає ZMQ MCP Bridge, який у фоновому режимі збирає телеметрію від ботів.
* Надає кінцеві точки для TradingView Lightweight Charts (PnL, ринкові фічі).
* Приймає та транслює керуючі політики (adjust risk, pause, stop) від глобального Hermes Agent до ботів.

Команда ізольованого запуску:
  python -m src.quantum_edge_infra.automation.hermes_agent.dashboard_api

Очікуваний лог:
  Uvicorn running on http://0.0.0.0:8765

Етап 3: Торгові боти (Execution Plane)
--------------------------------------
Сутність: Виконавчі HFT/DCA мікросервіси. Перед підключенням до live-потоку кожен бот виконує процедуру прогріву (Warm-up): надсилає HTTP запит до QuestDB (порт 9000) для завантаження історичних тиків та наповнення локальної черги (`collections.deque`).

1. AI Scalper Bot (ML Scalper):
* Використовує асинхронну ML-стратегію `AdaptiveGridStrategy` (XGBoost).
* Слухає команди на порту 5559.
* Надсилає телеметрію кожні 2 секунди через ZMQ PUB (порт 5557) у форматі `StatusEnvelope`.
* Команда ізольованого запуску:
  python -m src.quantum_edge_core.ai_scalper_bot.run_bot

2. Dynamic DCA Bot (DynDCA):
* Повністю математичний бот сіткового типу (без ML-залежностей).
* Містить `L2Aggregator` для детекції стін ліквідності (Whale Walls) у стакані ордерів та Volatility Oracle (EWMA/Z-Score).
* Реалізує Magnet Effect (фронтран лімітних ордерів перед великими L2-стінами).
* Надсилає телеметрію через ZMQ PUB (порт 5567).
* Команда ізольованого запуску:
  python -m src.quantum_edge_core.dyn_dca_bot.main

Оркестрація через QuantumEdge.py (Production)
---------------------------------------------
Замість ручного запуску кожного модуля у різних вкладках терміналу використовується єдиний оркестратор:

1. Запуск всієї системи у фоновому режимі:
   python QuantumEdge.py start
   (Скрипт записує свій PID у файл `.quantum_edge.pid` та запускає процеси у фоні).

2. Запуск у форграунді (блокуючий режим):
   python QuantumEdge.py run

3. Перевірка статусу запущених процесів:
   python QuantumEdge.py status

4. Зупинка всіх процесів (у правильному порядку: Bots -> API -> Hub):
   python QuantumEdge.py stop

5. Запуск веб-дашборду Streamlit (на порту 8501):
   python QuantumEdge.py dashboard

Під капотом QuantumEdge.py виконує:
* **ZMQ Guard**: Перед запуском сканує порти [5555, 5557, 5558, 5567, 8765] та примусово вбиває процеси, які їх блокують.
* **Порт-проби (Readiness Probes)**: Послідовно опитує TCP-порти після запуску кожного сервісу для підтвердження його готовності перед стартом наступного.
* **Мультиплексування логів**: Зчитує stdout/stderr дочірніх процесів та перенаправляє їх у `quantum_edge.log`.
