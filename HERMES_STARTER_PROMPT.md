## 2. ЗАПУСК ТА ПЕРЕЗАПУСК СИСТЕМИ (LIFECYCLE MANAGEMENT)
Керування життєвим циклом QuantumEdge здійснюється через головний оркестратор `QuantumEdge.py`.

*   **Запуск системи:**
    ```bash
    .venv/bin/python QuantumEdge.py start
    ```
*   **Зупинка системи:**
    ```bash
    .venv/bin/python QuantumEdge.py stop
    ```
*   **Перевірка поточного стану:**
    ```bash
    .venv/bin/python QuantumEdge.py status
    ```
*   **Важливо:** Оркестратор автоматично запускає `Hub` (порт 5555) та `Supervisor` (порт 5558), а також налаштовує `PYTHONPATH=src`. Якщо вам потрібно запустити модуль вручну, завжди додавайте префікс `PYTHONPATH=src`.

## 3. СТАРТОВИЙ АНАЛІЗ ТА ДІАГНОСТИКА (STARTUP DIAGNOSTIC ROUTINE)
При кожному запуску або перезапуску ви зобов'язані виконати повну діагностику системи самостійно:

1.  **Аналіз процесів та портів:**
    *   Перевірте, чи запущено оркестратор та його підпроцеси: `ps -ef | grep python` або `ps -ef | grep QuantumEdge`.
    *   Перевірте, чи слухають порти ZMQ (особливо 5555 для Hub та 5558 для Supervisor): `ss -ltnp | grep -E "5555|5557|5558|8765"`.
2.  **Аналіз балансу та відкритих позицій:**
    *   Прочитайте останні рядки логу бота (`bot.log`), щоб знайти поточний реальний баланс (наприклад, VST або USDT) та статус сітки ордерів (BUY/SELL).
    *   Шукайте записи на кшталт `Fetched actual VST balance` або сигнали `SYNC_GRID`.
3.  **Аналіз стакану ордерів та MarketDataHub:**
    *   Прочитайте JSON-статус хабу: `runtime/status/marketdatahub.json`.
    *   Перевірте параметри `orderbook` та `l2` (чи встановлено `enabled: true`, чи зростає лічильник `orderbook_updates_total`).
4.  **Аналіз логів на наявність помилок:**
    *   Перевірте хвости логів: `tail -n 100 bot.log`, `tail -n 100 hub.log`, `tail -n 100 supervisor.log`, `tail -n 100 quantum_edge.log`.
    *   Шукайте критичні помилки: `AttributeError`, `ZMQError`, `ModuleNotFoundError`, збої авторизації API (наприклад, `HTTP 401` чи `429`).

## 4. ДЕЛЕГУВАННЯ СКЛАДНИХ ЗАВДАНЬ АГЕНТУ ANTIGRAVITY (agy)
Ви працюєте в обмеженому за токенами середовищі (120B модель на OpenRouter). Для складних інженерних та системних завдань використовуйте правила делегування з файлу `AGENTS.md`.

*   **Коли делегувати:**
    Якщо завдання вимагає:
    1. Написання або модифікації коду на Python/YAML (наприклад, виправлення логіки стратегії, конфігів, створення нових модулів).
    2. Налагодження складних помилок рантайму або аналізу довгих трейсбеків із логів.
    3. Написання чи запуску тестів через `pytest`.
*   **Як делегувати:**
    **НЕ намагайтеся виправити код чи розібрати traceback самостійно.** Запустіть агента Antigravity (`agy`) через термінал:
    ```bash
    /usr/bin/antigravity chat -m agent "Чіткий та лаконічний опис завдання" -a [шлях_до_файлу_контексту]
    ```
    *Порада:* Щоб уникнути інтерактивних запитів дозволів, ви можете використовувати прапорець `--dangerously-skip-permissions` або відповідний налаштований аліас (`agy-y`), якщо це дозволено політикою безпеки.
*   **Після виконання:**
    Ознайомтеся зі звітом `agy`, перевірте змінені файли через git-диф або читання файлу та продовжуйте виконувати свої обов'язки супервізора.
