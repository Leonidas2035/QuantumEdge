================================================================================
  PART 7: STRICT CODING GUIDELINES
================================================================================

  1. FINANCIAL PRECISION
     - NEVER use Python float for balance/price/order size in production.
     - Use decimal.Decimal or integer satoshi math.
     - numpy.float64 is acceptable ONLY for statistical indicators
       (RSI, MACD, OFI) where speed > penny-perfect precision.

  2. CONFIG VALIDATION
     - ALL config loaders live in supervisor/supervisor/config.py.
     - YAML key names MUST match dataclass field names exactly.
     - Positive-value fields raise ValueError on 0 or negative.
     - If you add a new config field: update dataclass + loader + YAML + this file.

  3. SECRETS
     - NEVER hardcode API keys. Use .env or os.getenv().
     - Key env vars: GOOGLE_API_KEY, BINANCE_API_KEY, BINANCE_API_SECRET.
     - Check .gitignore before every commit.

  4. IMPORTS
     - Absolute imports only: quantum_edge_core.supervisor.supervisor.config
     - NEVER use relative imports like "from supervisor import ..."
     - Common mistake: supervisor.supervisor vs supervisor.supervisor.supervisor

  5. LOGGING
     - Use module-level logger: logger = logging.getLogger(__name__)
     - NEVER use print() in production code.
     - Structured JSON logging for all telemetry events.

  6. CONCURRENCY
     - I/O bound (WebSockets, API calls): asyncio / uvloop
     - CPU bound (backtests, ML training): multiprocessing
     - NEVER mix threading with asyncio without proper bridges.

  7. DYNAMIC SPOT GRID (MODULE DETAILS)
     - Aggregator (`aggregator.py`):
       Processes L2 Order Book data and streams updates. It calculates mid-price (`mid = (best_bid + best_ask) / 2.0`) and spread, and extracts whale walls based on quantity thresholds. Polling frequency has been reduced to 1 Hz to prevent system overload (OOM issues). Data is published via ZeroMQ to downstream services.

     - Volatility Oracle (`volatility_oracle.py`):
       Maintains a rolling 7-day window of 1-minute close prices (up to 10080 data points).
       Calculates `returns = ln(P_t / P_{t-1})`.
       Standard deviation of returns is scaled to a percentage.
       Vol Index normalizes standard deviation: `vol_index = min(max(std_dev / 2.5, 0.0), 1.0)`.
       Grid spacing dynamically updates: `grid_spacing = min_spacing + vol_index * (max_spacing - min_spacing)`.

     - Dynamic Grid Strategy (`strategy_core.py`):
       Focuses on Continuous Maker Grid logic for SPOT markets.
       * Order generation uses `SYNC_GRID` events. The bot evaluates price boundaries: pauses entry if `price < grid_bottom` or `price > grid_top`.
       * Adjusts order sizes up to `max_qty_base` calculated from `quote_balance * exposure_pct / total_levels`.
       * Re-syncs grid when:
         - Initial sync (no prior price).
         - Macro regime or bias change from the supervisor.
         - Price drifts beyond `grid_spacing_pct` from `last_sync_price`.
       * `on_order_filled` directly generates counter-orders (BUY triggers a SELL, SELL triggers a BUY) offset by `grid_spacing_pct` to capture spread automatically.

     - LLM Supervisor (`supervisor.py` & JSON schema):
       Acts as a Macro-Economist, operating on a 5-minute cycle analyzing OHLCV candles (4h, 1h, 5m).
       Issues `LlmGridPolicy` JSON payloads specifying:
       - `trading_mode`: Defines state (e.g., `SPOT_GRID`).
       - `recommended_grid_top` / `recommended_grid_bottom`: Hard boundaries within which the grid operates.
       - `bias` / `market_regime`: Drives directional bias or grid adjustments based on broader market trends.
