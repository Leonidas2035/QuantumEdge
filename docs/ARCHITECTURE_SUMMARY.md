# Огляд архітектури QuantumEdge

Цей документ містить короткий опис структури проєкту QuantumEdge на основі головного `README.md` та фактичного наповнення репозиторію.

## 1. Meta-Agent: Оркестратор змін
Центральним елементом системи є **Meta-Agent** — контрольований оркестратор змін з інтегрованими шлюзами безпеки.

- **Призначення**: Сканування контексту проєкту, побудова промптів та створення структурованих наборів змін.
- **Модель безпеки**:
  - Режим "тільки патчі" за замовчуванням.
  - Оцінка кожної зміни політикою безпеки.
  - Обов'язкове проходження перевірок у тіньових робочих просторах (shadow workspaces) та через quality gates.
- **Артефакти**: Результати роботи зберігаються в `runtime/runs/<run_id>/`, включаючи звіти, патчі та виводи шлюзів.

## 2. Основні компоненти системи
Проєкт організований за модульним принципом:

- **AI Scalper Bot (`ai_scalper_bot/`)**: Основний торговий бот, що реалізує стратегії скальпінгу з використанням ML.
- **Supervisor Agent (`SupervisorAgent/`)**: Система нагляду, яка моніторить стан ботів, керує ризиками та забезпечує дотримання політик.
- **Market Data Hub (`MarketDataHub/`)**: Централізований вузол для збору та розповсюдження ринкових даних.
- **Core Modules (`src/`)**: Ядро системи, розділене на:
  - `quantum_edge_core`: Основна логіка.
  - `quantum_edge_infra`: Інфраструктурні компоненти.
  - `quantum_edge_ml`: Моделі та інструменти машинного навчання.

## 3. Структура репозиторію
- **`docs/`**: Детальна документація архітектури, операцій, безпеки та окремих модулів.
- **`tests/`**: Набір тестів для перевірки функціональності компонентів.
- **`scripts/` & `tools/`**: Скрипти для автоматизації, діагностики та розгортання.
- **`ui/`**: Користувацькі інтерфейси для керування та моніторингу (Control Center).
- **`examples/`**: Приклади завдань для Meta-Agent та конфігурацій.
- **`ops/`**: Конфігурації для розгортання (systemd, Windows services).

## 4. Швидкий старт та інструменти
Meta-Agent надає наступні інтерфейси:
- `diag` / `health` — діагностика та перевірка стану.
- `run-task` — виконання конкретного завдання.
- `watch` — режим очікування нових завдань.
- `ui` — запуск локального Центру Управління.
