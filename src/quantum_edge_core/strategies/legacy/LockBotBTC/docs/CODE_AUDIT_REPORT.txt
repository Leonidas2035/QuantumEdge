Scope: LockBotBTC, MarketDataHub (lockbot), SupervisorAgent (lockbot policy/control). Read-only audit.

A) Executive Summary
- Hub ingestion: PASS. LockBotBTC subscribes to MarketDataHub lockbot_md.v1 topics via ZMQ SUB (lockbot_btc/ipc/hub_subscriber.py:13-52) and parses msgpack LockbotMarketEvent.
- Supervisor control: PASS. Commands consumed from CMD_TOPIC `LOCKBOT:BTCUSDT:cmd` (lockbot_btc/main.py:88-141) with schema validation (lockbot/contracts/lockbot_control_v1.py:12-38).
- DDN layer: PASS/PARTIAL. Safety/step sizing implemented in DDNEngine (lockbot_btc/ddn/engine.py) with rate-limit, band clamps, cost guards; no advanced indicators beyond market snapshots.
- Policy/strategy: PARTIAL. Strategy logic lives in SupervisorAgent policy runner (trend/range) (SupervisorAgent/supervisor/lockbot/policy_runner.py, strategy_range.py, strategy_trend.py); LockBotBTC itself has no strategy beyond executing Supervisor intents through DDN.
- Replay/backtest: PARTIAL. Replay harness exists (tools/lockbot_replay.py, lockbot_btc/replay/*) consuming lockbot_md JSONL and Supervisor policy configs; execution still dry-run by default.
- Execution: PARTIAL. ExecutionManager supports DRY_RUN/DEMO_TESTNET/LIVE_MAINNET with BinanceFuturesExecutor (lockbot_btc/execution/binance_futures.py) but auto_submit defaults false and allow_live_mainnet defaults false.
- Warm path/QuestDB: PASS for writing (MarketDataHub quest_writer), LockBotBTC only consumes hub streams; no direct DB reads.
- DDN + execution separation: PASS. Order plans generated by DDN, guarded by ExecutionGate, tracked in OrderTracker and ledger JSONL.

B) System Architecture
- Entrypoint: python -m LockBotBTC.lockbot_btc.main (--config config/lockbot_btc.yaml) (lockbot_btc/main.py:603-620). Runs asyncio service; tasks: market loop, cmd loop, heartbeat, optional account loop.
- Packages: lockbot_btc (service), lockbot (contracts), tools (replay CLI), docs (contracts/runbooks), config (lockbot_btc.yaml).
- State components:
  - BotState (lockbot_btc/state/bot_state.py): command dedup/cache, last decisions, execution status.
  - MarketState (lockbot_btc/state/market_state.py): mark_price, vwap_d, band_1/2, avwap, liq_heatmap, funding_rate, volatility estimator.
  - AccountState (lockbot_btc/state/account_state.py): positions, margin, distance_to_liq, timestamps.
  - OrderTracker (lockbot_btc/state/order_tracker.py): client_order_id -> status, ack timeout detection.
  - ExecutionLedger (lockbot_btc/execution/ledger.py): JSONL append for exec events.
- Runtime loops:
  - _market_loop (lockbot_btc/main.py:147-155): consumes hub events queue, updates MarketState.
  - _account_loop (lockbot_btc/main.py:181-189): consumes hub account topics if configured.
  - _cmd_loop (lockbot_btc/main.py:191-204): processes Supervisor commands -> DDN -> ExecutionManager -> publishes ack/status.
  - _heartbeat_loop (lockbot_btc/main.py:206-219): periodic status publish + execution gate tick.

C) Integration & Dataflow
- MarketDataHub -> LockBotBTC:
  - Endpoint: hub_sub_endpoint (default ipc:///tmp/quantum_market_data.ipc) via zmq.SUB (lockbot_btc/ipc/hub_subscriber.py:21-43).
  - Topics (config/lockbot_btc.yaml:8-15): BTCUSDT:mark_price_1s, vwap_d, vwap_bands_d, avwap, liq_heatmap (schema lockbot_md.v1).
  - Schema decode: msgspec LockbotMarketEvent (MarketDataHub/lockbot/schema.py:7-18).
  - Payload handling: handle_market_event routes mark_price_1s, vwap_d, vwap_bands_d, avwap, liq_heatmap, funding_rate (lockbot_btc/main.py:130-175). Volatility derived locally from mark_price series (lockbot_btc/state/market_state.py:23-39).
- SupervisorAgent -> LockBotBTC:
  - CMD_TOPIC: LOCKBOT:BTCUSDT:cmd (lockbot/contracts/lockbot_control_v1.py:14). SUB via ControlSubscriber (lockbot_btc/ipc/control_subscriber.py:12-40).
  - Command schema validation: validate_command enforces cmd types and fields (lockbot/contracts/lockbot_control_v1.py:36-68).
  - Supported cmds: SET_REGIME, SET_DELTA_TARGET, EXEC_STEP, PANIC_LOCK, EXIT_LOCK, PAUSE, RESUME, ARM_EXECUTION, DISARM_EXECUTION, CANCEL_ALL (lockbot/contracts/lockbot_control_v1.py:18-31).
- LockBotBTC -> SupervisorAgent:
  - ACK_TOPIC: LOCKBOT:BTCUSDT:ack (lockbot/contracts/lockbot_control_v1.py:15). Built in _build_ack and published in _cmd_loop (lockbot_btc/main.py:191-204, 241-260).
  - STATUS_TOPIC: LOCKBOT:BTCUSDT:status (lockbot/contracts/lockbot_control_v1.py:16). Published on each command and heartbeat (lockbot_btc/main.py:191-219, 262-320).
  - EXEC_TOPIC: LOCKBOT:BTCUSDT:exec (lockbot/contracts/lockbot_exec_v1.py:12). Emitted by ExecutionManager via BotPublisher when execution events occur (lockbot_btc/execution/manager.py:122-140, 271-289; lockbot_btc/ipc/publisher.py:16-29).
- Warm path / QuestDB:
  - MarketDataHub writes lockbot_md topics to QuestDB (MarketDataHub/tsdb/quest_writer.py via LOCKBOT_TABLE_MAP). LockBotBTC does not read QuestDB; it only consumes live hub topics (no DB IO in codebase).

D) Strategy / Policy Audit
- Location: strategies live in SupervisorAgent, not in LockBotBTC.
  - Policy runner: SupervisorAgent/supervisor/lockbot/policy_runner.py orchestrates regime detection and strategy selection, issues control commands via LockbotControlClient.
  - Strategies: strategy_range.py and strategy_trend.py implement decision logic returning PolicyIntent/StrategyDecision (SupervisorAgent/supervisor/lockbot/strategy_range.py, strategy_trend.py).
  - Inputs to policy runner: MarketDataHub lockbot_md via LockbotHubSubscriber (SupervisorAgent/supervisor/lockbot/hub_subscriber.py:13-155) supplying MarketSnapshot (ohlcv, vwap, bands, heatmap, funding) and Bot status via ControlClient polling.
  - Outputs: control-plane cmds (SET_REGIME, SET_DELTA_TARGET, EXEC_STEP, PANIC_LOCK) built with build_command (supervisor/contracts/lockbot_control_v1.py) and sent over CMD_TOPIC (supervisor/lockbot/control_client.py:70-92).
- LockBotBTC internal strategy: none. It interprets commands into DDNIntent (_build_intent, lockbot_btc/main.py:321-359) and applies DDNEngine evaluate (lockbot_btc/ddn/engine.py:47-158). Verdicts: ALLOW/MODIFY/REJECT/PANIC_ONLY.
- Safety gates (DDN):
  - Stale data: _is_stale on market/account lag vs panic_on_lag_ms (ddn/engine.py:151-158).
  - Liq risk: _is_liq_risk vs min_distance_to_liq_bps (ddn/engine.py:160-165).
  - Rate limit: max_steps_per_minute (ddn/engine.py:120-130, 226-236).
  - Cooldown after reject: cooldown_ms_after_reject (ddn/engine.py:132-140).
  - Margin guard: max_margin_usage (ddn/engine.py:142-147).
  - Band clamp: target/band_low/band_high vs net_delta (ddn/engine.py:188-209).
  - Cost guard: fee+slippage+funding vs expected_edge_bps/min_expected_edge_bps (ddn/engine.py:219-224, 211-218).
- Outputs: OrderPlan list (side, reduce_only, qty, type=LIMIT|MARKET for panic) (ddn/engine.py:166-217). ExecutionManager may block submission based on gate/account lag/mode (execution/manager.py:160-223).
- If no strategy found: Statement: LockBotBTC has no standalone strategy; relies on Supervisor policy runner. Evidence: no strategy modules under lockbot_btc beyond DDN; decisions originate from commands.

E) Indicators / Features Inventory
- Computed in MarketDataHub (lockbot engine):
  - mark_price_1s (TOPIC_MARK_PRICE_1S) from on_mark_price (MarketDataHub/lockbot/engine.py:47-73).
  - vwap_d (session VWAP) and vwap_bands_d (±1/±2 std) from _update_vwap (MarketDataHub/lockbot/engine.py:95-151); uses trade price*qty accumulation; emits every vwap_publish_interval_ms (default 1000ms).
  - ohlcv_1m/5m/15m from _update_ohlcv/_publish_bar (MarketDataHub/lockbot/engine.py:153-206).
  - avwap (anchored VWAPs: lock_entry/trend_start/liq_sweep) from _update_avwap (MarketDataHub/lockbot/engine.py:208-243); anchors set on session reset and via set_anchor externally.
  - liq_heatmap from on_force_order and _update_heatmap (MarketDataHub/lockbot/engine.py:75-93, 245-305) using liquidation force orders; decays exponentially with half-life.
  - funding_rate events from on_funding_rate (MarketDataHub/lockbot/engine.py:75-88).
- Consumed in LockBotBTC:
  - mark_price_1s -> MarketState.mark_price + volatility_bps (lockbot_btc/main.py:130-139; state/market_state.py:23-39).
  - funding_rate -> MarketState.funding_rate (lockbot_btc/main.py:131-139).
  - vwap_d -> MarketState.vwap_d; vwap_bands_d -> band_1u/band_1l/band_2u/band_2l (lockbot_btc/main.py:139-149).
  - avwap -> MarketState.avwap (lockbot_btc/main.py:149-151).
  - liq_heatmap -> MarketState.liq_heatmap (lockbot_btc/main.py:151-154).
- DDN features used: mark_price, volatility_bps (derived locally), vwap_d and bands (for context only stored), funding_rate, distance_to_liq_bps (computed from AccountState), margin_usage. No ADX/ATR/ADX etc.; no VWAP slope; no liquidation heatmap inside DDN currently.
- Supervisor policy runner features:
  - MarketSnapshot includes vwap_d, bands, ohlcv bars, heatmap summary, funding, mark price (SupervisorAgent/supervisor/lockbot/hub_subscriber.py:38-155).
  - RegimeDetector uses returns/vol/bands/heatmap (SupervisorAgent/supervisor/lockbot/regime_detector.py).
  - Strategies:
    - Range strategy uses band distances and heatmap imbalance to issue EXEC_STEP trim/add near bands (strategy_range.py:14-95).
    - Trend strategy uses regime/trend strength to SET_DELTA_TARGET and EXEC_STEP directions (strategy_trend.py:13-88).

F) DDN Layer Audit
- Implementation: lockbot_btc/ddn/engine.py with config lockbot_btc/ddn/config.py; loaded from config/lockbot_btc.yaml.
- Guards/precedence:
  1) Stale data or PANIC triggers -> PANIC_ONLY (ddn/engine.py:116-171).
  2) Rate limit / cooldown -> REJECT (ddn/engine.py:120-141, 226-236).
  3) Margin cap and distance-to-liq -> REJECT or PANIC (ddn/engine.py:142-170).
  4) Profile changes (SET_REGIME/SET_DELTA_TARGET) -> ALLOW/MODIFY with adjusted bands/targets (ddn/engine.py:172-187).
  5) Step sizing by min/max notional, volatility scaling (ddn/engine.py:189-205).
  6) Band clamp on net_delta (ddn/engine.py:188-209).
  7) Cost guard (fees+slippage+funding) vs expected_edge/min_expected_edge_bps (ddn/engine.py:211-224).
- Outputs: DDNDecision {verdict, recommended_step_qty, order_plans, reasons, expected_cost_bps, adjusted targets/bands}.
- Execution mode: default DRY_RUN; auto_submit_on_allow defaults false (config/lockbot_btc.yaml:46-54). Gate requires ARM_EXECUTION cmd to arm and mode DEMO_TESTNET/LIVE_MAINNET.

G) Execution / Order Lifecycle Audit
- Adapter: BinanceFuturesExecutor (lockbot_btc/execution/binance_futures.py) using REST Client; URL default testnet; requires env keys. Supports submit_order, cancel_order, cancel_all with retries on retryable API/request errors.
- Idempotency: clientOrderId = LBTC_{cmd_id[:12]}_{index:02d} (lockbot_btc/execution/manager.py:310-314). Plan IDs hashed for ledger.
- Reconciliation: OrderTracker updates from hub account deltas/snapshots (lockbot_btc/main.py:380-413) and marks unknowns as RECONCILIATION_MISMATCH (execution/manager.py:141-158).
- Safety gating:
  - ExecutionGate armed TTL, stale_account_ms, open_orders cap, symbol whitelist, reduce_only consistency, mark_price availability (execution/manager.py:160-223).
  - Panic mode blocks add actions if allow_reduce_only_in_panic is False (config true by default) (execution/manager.py:185-200).
- DRY_RUN: If mode DRY_RUN or auto_submit_on_allow false, execution events emitted as EXECUTION_DISABLED (execution/manager.py:163-179).

H) Test Coverage & Reliability
