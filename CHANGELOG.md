# QuantumEdge Changelog

Усі зміни, рефакторинг, виправлення в коді та налаштування записуються у цей файл для підтримки консистентності роботи агентів.

## [2026-06-22] - Інтеграція Hermes Agent та міграція на BingX
- **Видалення Binance:** Повністю вирізано всі залежності від Binance Futures та Spot (модулі `binance_futures.py`, `binance_feed.py`, `binance_spot.py`, `binance_spot_userstream.py`, `binance_usdm_userstream.py` тощо). Всі ринкові потоки даних тепер виключно працюють через `BingXLiveFeed`.
- **ZMQ & MCP Інструменти:** Створено локальні інструменти для Hermes:
  - `zmq_mcp_bridge.py`: Агрегує статуси ботів (`ai_scalper` та `dyndca`) та надсилає керівні політики через порт 5558.
  - `data_mcp_bridge.py`: Дозволяє Hermes зчитувати швидкі знімки ринку через ZMQ (порт 5555) та виконувати SQL-запити до QuestDB через HTTP API (порт 9000).
- **FastAPI Dashboard Bridge:** Створено `dashboard_api.py`, який замінив старий Supervisor на порту 8765. Він працює як проксі-сервер, що викликає ZMQ міст у фоновому режимі та транслює метрики на веб-фронтенд без блокування основного потоку.
- **Оркестрація:** З `QuantumEdge.py` остаточно вирізано застарілий Python-базований `SupervisorAgent`. Тепер оркестратор послідовно запускає: `MarketDataHub -> HermesAPI Bridge -> AIScalper -> DynDCA`, делегуючи всю високорівневу бізнес-логіку автономному глобальному `Hermes Agent`.
- **Ризик-Менеджмент:** Створено декларативний файл `risk_policy.md` у директорії `hermes_agent/instructions`, який жорстко задає правила управління ризиками (напр., No-Loss, ліміти drawdown). Legacy-файл `HERMES_STARTER_PROMPT.md` позначено як `[DEPRECATED]`.


## [2026-06-21] - Архітектурне розділення ботів та оркестрація
- **Конфігурація (processes.yaml):** Боти розділено на три незалежні процеси (`ai_scalper`, `dyndca`, `lockbotbtc`) для ізольованого запуску під керуванням оркестратора.
- **Точка входу (run_bot.py):** Додано динамічне визначення стратегії через змінні середовища `STRATEGY_TYPE` та `QE_BOT_ID`.
- **Логіка стратегій (strategy_core.py):** Розкоментовано та відновлено ML-стратегію `AdaptiveGridStrategy` для використання ботом AI Scalper.
- **Виправлення багів (lockbot.yaml):** Усунено критичну помилку "ZMQError: Address already in use" при одночасному запуску скальпера і лок-бота (порт `bot_pub_endpoint` для LockBot змінено з `5557` на `5577`).
- **Оркестрація (Гермес):** Повністю переписано `HERMES_STARTER_PROMPT.md` з новими інструкціями щодо безперервного моніторингу (24/7 Market Analysis Loop) та чітким розділенням ролей між Гермесом та Antigravity (`agy`).
- **Документація:** Переміщено всі розрізнені текстові файли архітектури та звітів (`схема параметрів генерації google_genai.txt`, `SYSTEM_CNTEXT_DCA.txt`, `LockBot_Refactoring_Report_Antigravity.txt` та інші) у спільну директорію `Documentation/`.

## [2026-06-21] - Етап 2 — Розробка L2 Aggregator (Детекція Whale Walls)
- **Алгоритм детекції:** Реалізовано клас `L2Aggregator` для виявлення "стін" ліквідності у стакані ордерів (depth_l2). Алгоритм фільтрує віддалені рівні (max_depth_pct) та визначає аномальні об'єми відносно базису (wall_multiplier).
- **Інтеграція ZMQ:** Оновлено `zmq_receiver.py` для обробки топіку `depth_l2` за допомогою агрегатора.
- **Git Flow:** Зміни додано в репозиторій (`ab30bfd`).

## [2026-06-21] - Етап 3 — Розробка DCA Engine та інтеграція L2 (Magnet Effect)
- **Декоплінг логіки:** Повністю вирізано клас `DynamicDCAStrategy` з `ai_scalper_bot/.../strategy_core.py`. DCA-бот більше не залежить від XGBoost та ML-пакетів.
- **Математика сітки:** Реалізовано клас `DCAEngine` з підтримкою експоненційного розширення на основі Gamma-параметра та ATR.
- **Volatility Oracle:** Адаптовано клас `VolatilityOracle`, який розраховує множник кроку на основі Average True Range.
- **Magnet Effect (Фронтран):** Додано механізм зміщення ціни ордера (front-running). Якщо розрахункова математична ціна ордера знаходиться надто близько до L2-стіни ліквідності, ордер переміщується на один тік перед стіною.
- **Git Flow:** Зміни успішно закомічені (`c0095cf`) та завантажені у віддалений репозиторій.

## [2026-06-21] - Етап 4 — Розробка Grid Manager (Виконання та Take Profit)
- **Управління позицією:** Створено `GridManager` для розрахунку середньої ціни входу (`average_entry_price`) та поточного розміру позиції.
- **Take Profit & NO-LOSS:** Імплементовано логіку автоматичного виставлення та пересування (trailing) ордера Take Profit при кожному усередненні. Додано жорстку перевірку (Sanity Check) на неможливість виставлення збиткового TP.
- **Order Router:** Додано базовий клас `OrderRouter` (заглушка) для симуляції відправки та скасування ордерів (з параметром `reduce_only`).
- **Конфігурація:** До `DynDCAConfig` додано параметри цільового прибутку (`base_profit_pct` та `funding_comp_pct`).
- **Git Flow:** Зміни закомічені (`cf7ae44`) та завантажені в репозиторій.
